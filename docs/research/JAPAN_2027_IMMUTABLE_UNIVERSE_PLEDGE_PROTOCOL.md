# 2027年の予測対象レース一覧：元コミットとサーバー時刻を固定するプロトコル

**2026-11-21設計。事前登録用ソフトウェアと合成テストのみ。現時点で真正な2027年レースに対する事前予測・対象一覧の提出・結果採点は0件。**

## 先行する観測選択研究から、なぜ必要か

[2022–24年の観測経路と選択](JAPAN_2022_24_OBSERVATION_PATHS_RESULTS.md)では、後年に記録が残る集団と残らない集団のモデル間差が、観測機会を揃えると不確実になった。[2027年予測分母・未観測順位の上下限](JAPAN_2027_FROZEN_UNIVERSE_RANK_BOUNDS_PROTOCOL.md)で、未予測レースと結果未取得レースを分母から消さない解析器は整った。しかし、その解析器へ**レース後に都合のよい対象一覧CSVを渡せる**ままでは、対象レースの事前固定が保証されない。

今回の[新しいコード](../../scripts/ecology_japan_2027_immutable_universe_pledge.py)は、予定対象レースの私有CSVを、元の馬別予測ファイル・その公開集計コミットメント・[既存の予測／Source SHAのバンドル](JAPAN_2027_GITHUB_PUSH_ATTESTATION_PROTOCOL.md)と**バイト単位のSHA256で結び付け、GitHub上の独立した最初のpushの時刻と元Blobへ照合**する。

## 事前の封印（結果が一つも公開される前）

必要なファイル：

1. **非公開の対象一覧CSV**：ヘッダーが厳密に`race_id,race_start_at_jst,eligibility_known_at_jst`。各行にはJRA名前空間のレース識別子、JSTオフセット+09:00付き発走日時、一覧への登録・適格性を知り得た日時を記録。重複／未来の既知時刻／レース期間2027-01-01〜2027-06-30外／対応する凍結予測のレース漏れは拒否。最大500レース。**これは提供された私有一覧であり、JRAが全対象を保証した証拠ではない。**
2. **元の非公開馬別予測ファイル**：既存2027年凍結処理で得たM0/M1/M2の出走行、真のレース前の既知時刻、現在までに既に観測された履歴だけを含む。SHA256は既存の公開集計マニフェストに照合する。
3. **元の公開可能な予測集計マニフェスト**：馬名・個体別予測・レースIDを含まず、レース数・出走数・個体数・予測ファイルSHA・入力ファイルSHAを宣言する。
4. **元のSource／モデル予測の公開集計バンドル**：2018–21年など旧予測ではなく、2027年の本番**レース前**に作る必要があるバンドル。Source A/Bの2022〜24年実測結果をこのファイルへ偽装流用しない。バンドル内部の予測マニフェストSHA／非公開予測SHAと完全一致しなければ拒否。

すべての入力のSHAが一致した後に、**別の公開集計ファイル**を作る。含むのは、非公開対象一覧のSHA256、予測SHA、元Source／予測バンドルSHA、予測対象1レースの出走数・馬数、対象一覧で予測していないレースの件数、最初の予定発走日時、モデル凍結日時、限界の注記だけ。元のレースID／馬ID／父母ID／個体別予測／競走明細は含めない。

この一つのファイルを **`docs/commitments/2027-universe/<32桁の内容SHA>.json`** の形式で**新規ファイルとして**作成する。以前のパスを上書き・再登録してはならない。予測のない対象レースは**0にする必要はない**：その場合も宣言された欠測数を記録し、後の全対象のモデル優越性評価をHOLDとする。

## GitHub実サーバーで確認できる範囲

[新しいpush専用GitHub Actions](../../.github/workflows/ecology-japan-2027-immutable-universe-push.yml)は、`docs/commitments/2027-universe/*.json` の**新規追加**だけを許可する。PR／手動`workflow_dispatch`／既存ファイルの変更／ブランチ初回の不透明なpush／GitHub Actions再実行を新しい事前登録の証拠とは認めない。

- GitHub REST `actions/runs/{run_id}` のサーバー管理`created_at`は、予測を凍結した日時以降、**宣言された対象一覧で最も早い発走の前**になければならない。Git作者日時／手元PCの時刻／JRA-VAN MakeDateは代用不可。
- 元のコミットSHA、期待する`push`イベント、本番専用ワークフローパス、`run_attempt=1`、GitHubのrepositoryを照合する。
- **実行中のGitHub Actions自身は、終了済み成功を証明できない**。最初のpushワークフローの時刻だけを条件付きで検査し、レース後に指定の元SHAで元ファイルをGitHub Contents APIから再取得し、SHA・Git Blob SHA1・元バイト・`status=completed/conclusion=success`を別途照合する。
- 以前の**予測・Source本体の元バンドル**についても、別の本番ワークフローの元SHA・最初のpush成功を[既存の元コミット検証器](../../scripts/ecology_japan_2027_github_push_attestation.py)で照合する。二つの成功済み元コミットが揃って初めて、本プロトコルの「予測分母の封印」という条件が満たされる。

レース後に手元の対象一覧CSVが1バイトでも書き換わった場合、SHAが合わず**採点を開始しない**。元の馬別予測、元のSourceバンドル、元予測公開マニフェストも同じ。これにより**後年の観測結果を見て対象レースを追加・削除して有利な見かけの予測成績を作る**操作を検出する。

## レース後の分母監査との接続

`sealed-score`コマンドは、上記二つの元コミットをGitHubサーバーと元ファイルから独立に確認し、非公開の対象一覧CSVと元予測のSHAを開封した後、[元の未観測順位の部分識別器](../../scripts/ecology_japan_2027_denominator_rank_bounds.py)を呼ぶ。

その結果、(i)予測したレース、(ii)事前対象一覧にあったが予測を提出しなかったレース、(iii)完走結果が判明したレース、(iv)未取得／部分取得／DNF／取消などで順位が不明なレースを、**レース後に分母変更することなく**報告する。未提出の対象レースが1つでもあれば全対象の予測改善はHOLD。未観測レースの着順境界は**全馬が完走して1〜Nの着順を持つ仮想ケースの数学的な最小／最大**で、95%信頼区間ではない。

**この封印を検証できても、「一覧がJRA全体の完全なレース集合」「JRA-VANの出走情報が実際にその時刻に公開されていた」「正式登録IDが真に照合された」とは証明されない。** GitHubのサーバー時刻が証明できるのは公開集計ファイルの存在時刻であり、元の民間／公式データの真正な公開時刻は独立の確認が要る。

## 科学的意義

2022〜24年の情報利用モデルでは、**観測され続けた個体だけで比較すると情報価値が高く／低く見える**という選択バイアスと、モデル自身の切替ルールが過去履歴の構成差を作る問題を確認した。2027年の正式な前向き試験では、同じ過ちを繰り返さないよう、**予測を提出する時点で何を分母とするかを外部時刻付きで封印**する。

これは動物生態学におけるinformative observationの研究設計へ接続するが、生物学的適応や真の遺伝的関連を推定したわけではない。
