# 2027年の予測評価：レースの分母・欠測・着順の部分識別

**2026-11-21：正式JRA/NARレースの新しい実測結果ではなく、将来の前向き試験を不正確に肯定しないためのコードと架空データ検証。実際の2027年事前予測は0件。**

## 背景：結果が手に入るレースだけを採点すると結論が変わり得る

[公式ID・情報公開時点を固定する既存の2027年予測台帳](JAPAN_2027_POINT_IN_TIME_LEDGER.md)と[GitHubサーバー時刻での事前登録](JAPAN_2027_GITHUB_REAL_SERVER_REHEARSAL_RESULTS.md)のコードはすでにある。しかし現在の採点関数は**完全順位1..Nが得られたレースだけ**でM0、M1、M2の馬均等RMSEを計算する。未取得の結果、途中棄権・取消、最初から予測を登録しなかったレースを分母から黙って消すと、2022〜24年の[観測選択研究](JAPAN_2022_24_OBSERVATION_PATHS_RESULTS.md)と同じ種類の選択バイアスが、将来予測の証拠にも入り込む可能性がある。

今回の新しい[スクリプト](../../scripts/ecology_japan_2027_denominator_rank_bounds.py)は、**元のM0/M1/M2予測・元の採点・モデル係数・血統・学習法を一切変更しない**。将来、ユーザーが許諾を得た個別データを私有環境から与えた場合に、予測対象全体の分母を固定して、未採点レースが成績に与え得る最大の影響を数量化する。

## 入力・プライバシー

1. 実レースの前に保存した**非公開の馬別予測JSON**、それに対応する**公開可能な全体集計予測コミットメントJSON**。既存の `ecology_japan_2027_point_in_time_ledger.py freeze` が出力する形式。私有予測のバイト内容をSHA256で照合し、違いがあれば拒否。
2. 後日公表された（またはまだ未公表の）**結果CSV**。結果がゼロでも欠測として扱える。取得済みの部分的な着順を、勝手にレース全体の完全順位と呼ばない。
3. 任意の**別系統で事前に準備した対象レース一覧CSV**（PRIVATE）：`race_id,race_start_at_jst,eligibility_known_at_jst`。全部 `JRA:` 名前空間、JST +09:00、2027-01-01〜2027-06-30内であり、各レースの掲載・対象適格性は**当該予測のas-of以前に確認済み**でなければHOLD。予測済みレースが一覧外、同名重複、予測開始時刻との不一致、未予測の対象レースがあれば明示的に拒否／HOLD。
4. 必ず**集計だけ**を書き出す。元の馬名、血統登録番号、レースID、個別予測、個票の着順は公開しない。

**この一覧CSVは依然としてユーザーが提出した私有資料であり、それ自体がJRA/NAR全対象の公的・独立に認証された分母ではない**。実際の全レース対象性を証明するには別途ライセンスと記録の時刻・出所、GitHubへの事前登録が必要。

## 欠測の4状態

各事前予測レースは、**全馬が同じレースの1〜Nの完全順位で結果が確認済み**、**まだ1頭も結果がない**、**一部だけ結果がある（欠測）**、**失格・途中棄権・取消・順位や分母の矛盾などで正規化順位の目的変数が定義できない**、のいずれかに分類。馬数・レース数を事前予測の全分母から計算して公表する。

**目的変数が定義できないレース**では順位を捏造しない。全対象の予測比較は**HOLD**し、取得済みの完全順位レースに条件付けた結果は別途記述するだけに留める。

## 未取得レースでのM2対M1・M0の「あり得る全順位」境界

予測`p_base`（M1またはM0）と親族追加モデル`p_M2`はどちらも0〜1の固定値。正規化順位`y=(rank−1)/(N−1)`はN人の完走で0,1/(N−1),…,1になる。出走iについて

`w_i * [(y_i−p_base_i)^2−(y_i−p_M2_i)^2] = 2 w_i (p_M2_i−p_base_i) y_i + w_i(p_base_i²−p_M2_i²)`。

**馬の重みは元の事前予測の全レースを通した出走回数で決める。** 1頭につき合計重みが1/全馬数になるよう `w_i=1/(H×n_i)` とする。欠測レースだけで重みを再正規化してはいけない。

上式は順位yに関して線形。**並べ替え不等式**により、傾き `2w_i(p_M2_i−p_base_i)` の大きい馬に小さいyを割り当てると全体のMSE差が最小、傾きの小さい馬に小さいyを割り当てると最大となる。したがって**結果未取得のレースが、仮に全馬完走の1〜N着になった場合に限って**、あらゆる可能な順位に対する正確な下限・上限が求まる。すでに確定したレースのMSE差は固定し、未取得レースの下限／上限を足す。

この区間は**統計的95%信頼区間ではなく、未観測の完走順位の可能性に関する決定論的な上下限**である。一部だけ結果が分かるレースについても、部分結果を使って最も都合のよい順位を補うのではなく、全順位の並べ替えを許した保守的な区間を報告する。

M1−M2のMSE差の**最小値が正**なら、仮想的な全馬完走の全順位割当で常にM2がM1より良い。逆に最大値が負なら常にM1有利。上下限が0を挟めば、未取得結果だけで優劣が逆転し得る。M0−M2にも同じ処理を適用する。**本当にM2が有用だと主張するには、両方の比較で下限が正であることのほか、実データの出所、正しい分母、レース前の予測凍結時刻、独立未来試験、十分な標本と依存性区間の確認が要る**。

どのレースでも途中棄権・失格などにより順位1〜Nの対象が定義できない場合は、全予測集合の「完全順位を前提としたMSE差」という量自体が成立しないため、全体境界はHOLD。取消を最下位として補う、勝率に置き換えるなどの暗黙の処理は禁じる。

## 追加の検証と運用コマンド

コードは元の`score()`を先に実行し、SHA、予測件数、未来の結果公開時刻、元レースID、重複、順位の誤り等の拒否条件を保持する。さらに、**全結果が存在する場合、上下限が一致し、元の馬均等RMSEの二乗差に1e−10以内で一致**しなければHOLDとする。架空の3頭×2レースについて、すべての順位置換を列挙して上下限が正確であることもテストする。

```bash
python scripts/ecology_japan_2027_denominator_rank_bounds.py \
  --private-frozen-forecast /private/pre_race_frozen_forecasts.json \
  --aggregate-forecast-commitment /private/pre_race_aggregate_commitment.json \
  --published-results /private/later_verified_results.csv \
  --private-eligible-universe /private/pretarget_eligible_race_list.csv \
  --aggregate-out /private/2027_denominator_sensitivity_aggregate.json
```

**すべてのテストは架空のID・レース結果のみ**。CIでは実馬・JRA-VAN等の個票取得を一切せず、`docs/commitments/2027`に真正な事前予測が存在しないことも検査。生成したコードは外部GitHubサーバーや公的登録の真正性を認証できないので、出力全体のstatusは**HOLD_NOT_INDEPENDENTLY_ATTESTED_PROSPECTIVE_SOURCE_AND_UNIVERSE**とし、たとえ人工例で上下限が正でも**2027年の実モデル成績には昇格しない**。
