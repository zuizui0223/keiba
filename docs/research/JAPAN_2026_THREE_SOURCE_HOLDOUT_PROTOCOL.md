# 2026 third-source bridge: old pedigree/history -> HF archived identity -> public JRA results

**Protocol frozen 2026-11-17 before inspecting any 2026 *linked-family* result.** Existing 2022–24 outcome/parent/strong-baseline benchmarks, and partial January–March 2025 HF outcomes, have already been inspected. This is a **new historical out-of-period source comparison**, not a prospective registered study, and not official pedigree validation.

## Three sources and permitted roles

**A: Historical parent IDs and training.** \`ayuser/horse-racing-in-japan\`, 2010–2021 original archive SHA256 \`c72d280ce82b583686caca6773fd1a7589917f9b10b96a25f8d4e96f9b7a4a8f\`. Original redistribution license not verified. Parent identifiers and historical competing horses' prior performance come solely from A; no year later than 2021 is ever used to fit coefficients or parent-history features.

**B: An archived intermediate identity witness, NOT an outcome validation source.** \`KBlueLeaf/jp-racing-horse\` horse/race SQLite (1990–2025-03-27) SHA256 \`7c6717f6f081f957721396d1e0e7296b4be3eeaa2fe1a657b41a4b5358474be9\`. Never assume B.hid equals A.horse_id. Require exact normalized name plus >=2 distinct matching race days, finish ranks and distances from 2021 or earlier for A->B as already audited, with ambiguous names quarantined.

**C: A new publicly available outcome-only source.** \`whitedogk/jra-condition-app\` repository root \`jra-results-actual.csv\` (source says JRA HTML-derived; see source repository). Earlier audit of this exact root path yielded 141,394 rows restricted to 2023–early 2026, SHA256 \`ca14ff253018433e8e14bc583628f85ca909195d5e4edb42c6d1e2ade939ba6f\`. **The README describes a larger 2016–2026 dataset, but the actual root CSV and its committed manifest differ**; do not infer dates from README. Source C has no official horse stable ID, no parent IDs and no genomic data. It contains horse *name*, date, finish, course, race number, distance, surface; its original racing-record redistribution rights are not independently verified. It must be downloaded transiently and pinned by full SHA, and only aggregated metadata may be exported.

## Future-label-free identity design

1. A->B match uses only *pre-2022* history and exact unambiguous names; at least two exact days, ranks and distances on distinct days. The existing 20,400 match candidates are a source gate, not a JRA studbook ID certificate.
2. B->C match uses **only 2023–2024 outcomes in BOTH B and C** as identity witnesses. C horse name must match B's exact normalized name (NFKC, casefold, whitespace only), unique among already matched A IDs; and each candidate requires >=2 **different pre-2025 dates** with identical date, distance, surface, rank. Do not use 2025 or 2026 ranks, payoffs, odds or race class to choose identity. Never guess a match by a Japanese naming prefix such as メイショウ.
3. C->2026 target row uses only the verified exact C normalized horse-name label from step 2. Each 2026 **race** must have 2..30 uniquely named horses, consecutive unique classified ranks 1..N, one winner, unique date/venue/race number/surface/distance, no incomplete or tied final ranks. If C is partial, exclude instead of assuming all starters have classifications. Within a valid race, score only the genuinely A->B->C-anchored subset.
4. Limit target dates to calendar **2026**, source C data release date ≤2026-11-17, no prior record or result from this calendar year is allowed in family/individual historical predictor features. Do not use 2025 as bridge: the B archive is partial to March, and 2025 source results have been partly inspected before this protocol.
5. Use source-A 2018–21 training, old historical own-racing performance/condition/parent-shared other-horse history and the already-frozen ridge α=100. Reproduce source-A feature formulas and the same original fixed 2022–24 no-kin and +kin score on that historical cohort as a parity check, where accessible. With 2026 source C, the strong model uses source-A-only birth-year/sex/recency features; no 2026 labels in predictors, no 2022–25 retraining.
6. Predeclare **feasibility threshold ≥30 uniquely mapped 2026 horses, ≥100 classifiable 2026 starts and ≥30 distinct race days**. If any fails: **HOLD_SPARSE_2026_ANCHORED_COHORT**, publish only aggregate source/identity support and do not calculate effect metrics. Even a pass is *survivor-only selected horses*, not new 2026 debutants nor all JRA/NAR starters.
7. If passing, compare fixed 0.5 midpoint, no-family, +family and strong own-history controls. Report pooled and per-calendar-month only where ≥100 eligible rows; horse and race-day cluster uncertainty; never manufacture results or retune models. A near-zero/negative result must remain visible.
8. An A->B->C exact historic-event chain **does not certify horse identity**. The B and C archives may have shared upstream official results; 2026 publication was accessible before this analysis, so this is retrospective temporal holdout, not genuine prospective collection.

## What would count as a decisive further step

A **licensed official JRA-VAN** \`RACE/RCOV\` sample with **blood registration number** joining the horse master and each \`SE\` (individual horse result) would replace all name-event inference; use \`RCVN\` where identifier field widths require it. This is the scientifically preferable route, but source rights and contract are essential. Do not mistake pedigree registration and breeding registration numbers as the same namespace. NAR requires its own licensed, source-specific identifier mapping; JV-Link alone does not constitute national JRA+NAR coverage.

**Caveat:** full pedigree relationship matrix A, anonymous 370-horse genomic G, heritability, MSTN effect, public odds or betting profit are still completely separate. No row-level source data or individual horse-level projections may be uploaded to GitHub. Code may be open, aggregate evidence only.
