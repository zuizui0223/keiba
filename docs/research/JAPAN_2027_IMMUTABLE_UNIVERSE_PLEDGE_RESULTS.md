# 2027年の対象レース分母をGitHub元コミットへ封印する実装：ソフトウェア検証結果

**2026-11-21 実行。GitHub Actions上のテストは成功したが、レース・馬・血統ID・対象時刻・予測はすべて架空。真正な2027年事前予測とSource JRA-VAN取得は0件。**

## 今回整ったもの

以前の[2027年の「予測済みレースと結果未取得レース」の分母監査](JAPAN_2027_FROZEN_UNIVERSE_RANK_BOUNDS_RESULTS.md)は、私有の対象レース一覧CSVを後から解析器へ与える設計だった。**一覧自体がレース前に決まっていたこと**は独立には証明できなかった。

新しい[ソースコード](../../scripts/ecology_japan_2027_immutable_universe_pledge.py)は、事前に決めたレース一覧の**元CSVのバイトSHA256**を、既存の馬別予測SHA、元の予測集計マニフェストSHA、Source／予測元バンドルSHAへ連鎖させる。公開するのはこれらのSHA、予定対象レース数、未予測レース数、凍結日時、最初の発走日時だけで、**実馬ID・馬名・レースID・競走個票・個別予測は含めない**。

外部時刻証明は二段階に分かれる。まず[新しい本番push専用ワークフロー](../../.github/workflows/ecology-japan-2027-immutable-universe-push.yml)が、新規に追加された匿名レース一覧コミットメントを**GitHubサーバーによるpush作成時刻**で検査する。検査時点でジョブの完了成功はまだ分からないため、後から**元40桁コミットSHA、成功済みrun ID、元Git Blob SHA、原ファイルのバイト一致**を再確認する。元予測バンドルも既存の[元コミット監査器](../../scripts/ecology_japan_2027_github_push_attestation.py)で別途確認する。

これらが両方成立してからのみ、privateの対象一覧・予測・元予測コミットメントを開封して、[未取得レースの順位上下限計算](../../scripts/ecology_japan_2027_denominator_rank_bounds.py)へ渡す。対象一覧に予測のないレースがあった場合、**個別の完走レースが高得点でも、全レースでM2が優れるという判定はHOLD**。

## 架空データで実際に反証した失敗モード

[新規20件の架空データテスト](../../tests/test_ecology_japan_2027_immutable_universe_pledge.py)は、3頭の架空競走馬の一つの2027年レース・仮のSource/モデルSHA・架空のGitHub API応答を使用した。次を検査する。

- レース一覧のSHAを結ぶ。馬・レースIDを含む公開ファイルは拒否
- 予測を提出していない追加対象レースを公表し、全対象のモデル優位をHOLD
- レース後に元対象一覧の既知時刻を1分でも変更すれば、元SHAが一致せず停止
- 元の馬別M1予測値・予測マニフェスト・Source/予測バンドルを変更すれば停止
- Githubの原本Git Blob SHA、40桁コミットSHA、完了成功run ID、ワークフロー名が一致しなければ停止
- GitHub Actions再実行（`run_attempt=2`）、サーバーrun作成が発走後、失敗済み元予測ワークフローは拒否
- 本番検証へ架空RESTレスポンスを直接注入する方法は禁止。合成試験だけ明示的な`allow_synthetic=True`を使用
- 途中棄権・順位欠落は勝手に完走順位へ補わず、全レースのMSE上下限判定をHOLD
- 実行中のGitHubジョブは、自らの完了成功を証明したとみなさず、後日の元バイト・最初の成功run確認へ分離

これは**現実のGitHub Actions実行で、架空の馬・架空のGitHub REST応答を用いた試験**。GitHub上の本物の予測コミットがレース前に作られたわけではない。リポジトリ内には`docs/commitments/2027`と`docs/commitments/2027-universe`の本番予測バンドルは作成していない。

本番での予定：
- `build`：privateの対象一覧／馬別予測／集計マニフェスト／元のSourceバンドルから、上書き不可・内容SHAで命名された新規公開集計バンドルを作成
- GitHubへ`push`後に本番push専用ワークフローで作成時刻を確認。既存の元予測バンドルも別途新規push／成功runが必要
- レース結果の公開後、`verify-original`で元コミットを照合し、`sealed-score`で**元の二つの証明が揃ってから**全レースの予測分母と欠測を評価する

具体的な必要ファイル・失敗時のHOLD条件は[プロトコル](JAPAN_2027_IMMUTABLE_UNIVERSE_PLEDGE_PROTOCOL.md)に記載。

## 現時点の科学的な判定

新しい機能で**レース前に同一の対象一覧を封印し、レース後に差し替えを検出できる設計**ができた。ただし、まだ真正な許諾済みJRA/NARデータで元の`run_attempt=1`・新規元コミットを生成してはいないため、**2027年の予測が前向きに検証されたとは言えない**。

GitHubの時刻が証明できるのは公開集計の存在時刻まで。JRAの全予定レース一覧が本当に網羅されていたか、JRA-VANのレース前情報が本当にその時刻に公表されていたか、馬の血統登録IDが公式に照合されているか、遺伝的な効果や馬券の優位性があるかは、別の証拠が必要。これらはすべてHOLD。

**科学的意義：先行する2022〜24年の観測選択・情報階層研究から得た弱点を、2027年の独立検証が都合のよい分母へ変わらないための測定契約に変換した。**
