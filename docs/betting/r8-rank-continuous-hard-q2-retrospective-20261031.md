# 京都8Rの実13:44次オッズ：価格の連続変化・仮定した閾値・無情報投票者ABMの比較

**2026-10-31 実装、元対象は2026-10-12京都8R、同一競走の保存済み実オッズ（12:21・13:26・13:44）。従って厳密にはRETROSPECTIVE ONE-RACE shadow replayであり、外部で将来予測を事前封印した結果ではない。**

## 目的：PR34/35の「人気順位の幾何学」とPR19の社会的反応を区別

[PR34](https://github.com/zuizui0223/keiba/pull/34) では、単勝価格のわずかな連続変化だけで順位が逆転し得ることを証明。[PR35](https://github.com/zuizui0223/keiba/pull/35) では、原本SHA固定の京都8Rで前半3組・後半7組の順位逆転が実際に記録されることを確認した。**順位逆転が実際に発生すること**と、**情報到着に起因する臨界的な群衆のフィードバックが発生すること**は、全く別の帰無仮説である。

ここでは唯一の厳密な既存3時点同一providerアーカイブ、京都8Rについて、**最初と中間だけで候補生成→後続実価格を後で開いて対照採点**のコード実行順序を固定した。これが将来の実オッズ3点取得に実装可能な比較の最小版となる。

## 再使用したオリジナル記録と時間の壁

- 競走：2026-10-12 京都8R、**11頭**。単勝 q0=12:21、q1=13:26。中間ワイド55組は元SRC_SHAで照合されるが、**この新価格モデルの説明変数には入れない**。
- 観測された目標は同一Yahoo/SportsNavi系の **13:44全11頭q2**。元Git blob SHA・発表時刻と受領時刻・予定発走前・全頭の馬番一致を既存コードで検証。
- モデル生成関数は意図的に **13:44のファイルを開かない**。候補すべてをUTF-8 JSON SHA256で固定した後、採点専用関数がアーカイブを読む。
- ただし、このコードとSHAのGitHub登録自体が2026-10-12の後。**前向き独立検証ではない。** レース結果・着順・馬券払戻・実投票量・実GPSは読まない。実市場M0は真の投票比率や実勝率でない。

## 候補：合計7手法、すべて事後的な探索モデル

初期2点を \(q_0, q_1\)（表示単勝オッズ逆数を17頭ではなく**11頭全件で正規化**）、時間差を \(\Delta t_{01}=65/60\) 時間、次を \(\Delta t_{12}=18/60\) 時間とする。

\[
v_i=\log(q_{1i}/q_{0i})\,\frac{\Delta t_{12}}{\Delta t_{01}},\quad
r=\frac{\max_i|\log(q_{1i}/q_{0i})|}{\Delta t_{01}}.
\]

価格モデルは \(q_{2i}(\alpha)\propto q_{1i}\exp(\alpha v_i)\)。
候補：持続 \(\alpha=0\)、単純logモメンタム \(\alpha=1\)、連続ゲイン \(\alpha=r/(r+0.10)\)、**仮定のハード境界** \(\alpha=\mathbf1[r\ge0.10]\) の4つ。0.10の単位は /hourで、PR19から借りた**事前に存在した探索的設計定数**であり、京都8Rの実データから推定した臨界値でも最適値でもない。

これに加え、既存の [PR19投票者ABM](../../scripts/keiba_endogenous_threshold_null_bridge.py) を**そのまま**使用。固定・滑らか・ハードの3反応政策を、**馬の新情報が最後まで到着しない**条件（arrival=5、4ラウンド）で、各30人工seed、同じ初期M0・同じseed系列で再現。PR19内部のハード境界は投票者のherding exponentを切り替える仮定であり、上記の市場価格モメンタムの\(\alpha\)ゲートとは**別の方程式**。これらを「同じ生理／社会メカニズム」とは呼ばない。

このモデル群は**親の馬ABM/PDEを再推定していない**。独立した馬ID履歴・GPSが取得できていないので、それらを学習・校正済みの馬シグナルとして混入しない。実装連携としては、前方馬ABM/PDEが独立した原情報を持つときだけ、その出力を既存PR19投票者ABMへ受け渡すという既存契約を保持する。

## 評価と識別の限界

実13:44の \(q_2\) を正解とし、7手法の価格指数TV（percentage points）と KL \((q_2\Vert\widehat q_2)\) を算出する。各手法の差は**同一実目標における差**で、人工seed 30の繰り返しは**30競走にならない**。

- q1の持続TVは、既存PR35で確認した実13:26→13:44価格指数TV **9.65636ポイント**。
- 元実価格では**7馬ペアで順位逆転**。
- CIで13:44のoriginal SHA-lockedソースを**別の採点ステップで開き**、次の値を算出した。

| 固定した方法 | 同じ実13:44価格指数に対するTV（pp） | 持続との差（pp） |
| --- | ---: | ---: |
| 直前のWIN持続（基準） | **9.656363** | 0 |
| logモメンタムをそのまま18分先へ延長 | **8.180965** | **−1.475398** |
| 連続ゲイン \(r/(r+0.10)\) | **8.657105** | **−0.999258** |
| 仮定の閾値ハードゲイン \(\mathbf1[r\ge0.10]\) | **8.180965** | **−1.475398** |
| 元PR19 固定・馬の新情報なし（30人工seed平均） | 9.978719 | +0.322356 |
| 元PR19 連続・馬の新情報なし（30人工seed平均） | 10.395475 | +0.739112 |
| 元PR19 閾値・馬の新情報なし（30人工seed平均） | 10.464642 | +0.808279 |

**モデル別の本データでの方向：** logモメンタムは持続より**15.28%**、連続ゲインは**10.35%**だけこの単一実価格目標に近い。ハードゲインがlogモメンタムに一致するのは、この初期2時点の観測rateが仮定0.10/hの境界を越え、ゲインが1となる**定義上の結果**。したがって**ハード閾値が実証された、モメンタム予測が一般に良いとは言えない**。さらに無情報ABMが持続より悪いのは、30回の**人工pseudo投票**に基づくもので、現実の独立/追随投票者が間違えた証拠ではない。

証拠：[GitHub専用CI #41195681757](https://github.com/zuizui0223/keiba/actions/runs/41195681757) は7テスト成功、13:44未読のfreeze実行成功、別ステップで13:44元SHA読込・全7モデル実価格採点成功。共通testsとv3.1 holdoutも同じheadでsuccess。30人工seedはあくまで**1つの実目標に対する30数値反復**である。
- どの手法が単一区間で一番近いかを見ても、**将来の市場で再現するか、実情報の閾値が存在するかは判定できない**。元オッズのprovider更新時刻自体も個々の投票時刻ではない。
